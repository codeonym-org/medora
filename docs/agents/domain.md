# Domain docs

Medora uses a single-context layout: root `GLOSSARY.md` and numbered decisions in `docs/adr/`.

Before exploring domain concepts or architecture, read the glossary and ADRs relevant to the work.
If these files do not exist, proceed silently. The domain-modeling skill creates them lazily as terminology and decisions are resolved.

Use glossary terms consistently in issues, proposals, code, and tests. Reconsider unfamiliar synonyms or note genuine vocabulary gaps for domain modeling.
If a proposal contradicts an ADR, identify that ADR and explain why the decision should be revisited.
